# PDR: translate&go

Документ описывает уже реализованный продукт: требования, архитектуру и поведение приложения `translate&go`. Источник истины - код в `Sources/OllamaTranslatorApp`. При расхождении кода и документа правится документ.

- Bundle id: `dev.boundlessend.translate-go`
- Платформа: macOS 13+
- Язык/стек: Swift 5.9, SwiftUI + AppKit, SwiftPM
- Внешняя зависимость: [HotKey](https://github.com/soffes/HotKey) для глобального хоткея
- Внешний сервис: локальный Ollama (адрес настраивается, по умолчанию `http://localhost:11434`)

## 1. Назначение

Меню-бар приложение для macOS, которое переводит выделенный в любом приложении текст через локальную модель Ollama по одному хоткею. Результат кладётся в системный буфер обмена, пользователь вставляет его через `Command-V`. Перевод полностью локальный: текст не покидает машину.

## 2. Цели и не-цели

Цели:
- перевод выделенного текста по глобальному хоткею без переключения окна
- работа поверх локального Ollama без ручного запуска сервера
- минимальная настройка: модель, язык перевода, язык интерфейса, хоткей, видимость в Dock и menu bar

Не-цели:
- собственный inference: перевод делегируется Ollama
- облачные провайдеры перевода
- редактирование/предпросмотр перевода в окне (результат отдаётся только через буфер обмена)
- автоматическая вставка перевода обратно в активное приложение (пишется только в буфер)

## 3. Пользовательские сценарии

1. Выделить текст в любом приложении, нажать хоткей, дождаться уведомления "готово", вставить через `Command-V`.
2. Повторное нажатие хоткея отменяет текущий перевод и запускает новый для нового выделения.
3. Открыть настройки из menu bar или Dock, выбрать модель из списка установленных, задать язык перевода и хоткей.
4. Открыть окно Q&A из menu bar для быстрой помощи по настройке.

## 4. Функциональные требования

### 4.1 Перевод по хоткею
- глобальный хоткей по умолчанию `⌃⌥C`, настраивается; хоткей обязан содержать модификатор
- по нажатию приложение читает выделенный текст, переводит его и записывает результат в буфер
- статусные уведомления: "перевод начат" и "перевод готов"
- при ошибке показывается уведомление с путём к лог-файлу; модальный алерт добавляется только для ошибок первичной настройки (нет Accessibility, не найден бинарь Ollama, сервер не стартовал); предыдущее содержимое буфера восстанавливается

### 4.2 Чтение выделенного текста
Двухуровневая стратегия (`AppDelegate.readSelectedText`):
1. Accessibility API: прямое чтение `AXSelectedText` из фронтального приложения (`AccessibilitySelectionReader`).
2. Фолбэк: активация приложения, синтетический `Command-C` (`KeyboardEventSender`), ожидание изменения буфера обмена (поллинг `changeCount`, до 100 попыток по 50 мс = ~5 с).

Требуется разрешение Accessibility (`AXIsProcessTrusted`). Пустое выделение, нетекстовое выделение (в буфер попало не-строковое содержимое) и таймаут - явные ошибки.

### 4.3 Перевод текста (`TranslationService`)
- HTTP POST на `<адрес сервера из настроек>/api/generate`, `stream=false`, `keep_alive=30m`, `num_ctx=8192`, таймаут 600 с
- длинный текст режется на чанки до 3000 символов по абзацам, при необходимости по предложениям; чанки переводятся последовательно и склеиваются через `\n\n`
- фиксированный промпт-инструкция (только перевод, без markdown, без альтернатив, с сохранением абзацев)
- постобработка ответа: удаляется только первая строка-болтовня модели вида `Here is the translation:` (известный префикс + двоеточие); сам перевод, включая строки с `*` и `**`, не изменяется
- ответы модели не кешируются (`urlCache = nil`)

### 4.4 Настройки (`SettingsViewModel`, `SettingsView`)
- модель: выбор из установленных (обнаружение через `ollama list` и `ollama ps`), кнопка обновления списка; текущая модель всегда показана в списке, даже если её нет среди установленных; автоподбор первой доступной модели выполняется только пока выбрана модель по умолчанию
- язык перевода: произвольный текст, по умолчанию `Русский`
- язык интерфейса: `english` (по умолчанию) или `russian`
- хоткей: запись новой комбинации (`HotkeyRecorderView`), сброс к `⌃⌥C`
- видимость в Dock и в menu bar
- адрес сервера Ollama (валидируется как http/https URL) и путь к бинарю Ollama (пусто = автоопределение)
- тумблер прогрева модели при запуске (по умолчанию включён)
- всё хранится в `UserDefaults`

### 4.5 Окна и меню
- окно настроек и окно Q&A (6 вопросов-ответов, локализованы EN/RU)
- статус-меню в menu bar: настройки, Q&A, выход
- меню приложения: настройки (`⌘,`), копирайт, выход (`⌘Q`)
- приветственное окно при первом запуске (флаг `hasShownWelcomeMessage`)

## 5. Архитектура

```
OllamaTranslatorApp (@main, SwiftUI App)
  └─ AppDelegate (@MainActor)  — оркестратор: хоткей → чтение → перевод → буфер
       ├─ SettingsViewModel    — состояние и персистентность настроек
       ├─ TranslationService   — POST /api/generate, чанкинг, очистка
       ├─ OllamaRuntimeManager — старт/прогрев/остановка локального сервера
       ├─ HotkeyManager        — регистрация глобального хоткея (HotKey)
       ├─ StatusMenuController — меню в menu bar
       ├─ PermissionManager    — запрос Accessibility/AppleEvents
       ├─ NotificationPresenter— пользовательские уведомления
       └─ DiagnosticLogger     — структурированный лог событий в файл
  Утилиты: AccessibilitySelectionReader, KeyboardEventSender, PasteboardSnapshot, AppText, AppError
  Модели: GenerateRequest/Response, HotkeyConfiguration, AppLanguage, OllamaDefaults
```

Стиль: функциональное ядро (чистые структуры `TranslationService`, утилиты), классы только для интеграций с внешними системами (процессы Ollama, события клавиатуры, menu bar, хоткей). `AppDelegate` изолирован на `@MainActor`, `OllamaRuntimeManager` - actor. Окна настроек и Q&A создаются общим `PanelWindowController`.

### 5.1 Управление конкуренцией
Каждое нажатие хоткея инкрементирует `translationGeneration`, отменяет предыдущую `Task` и проверяет актуальность поколения в ключевых точках. Это гарантирует, что в буфер попадёт результат только последнего запроса.

## 6. Управление Ollama (`OllamaRuntimeManager`)

- при запуске приложения: проверка доступности через `GET /api/tags`; если сервер не отвечает, запуск `ollama serve` как дочернего процесса и ожидание готовности (до 100 попыток по 100 мс = ~10 с); stdout/stderr процесса направлены в `/dev/null`
- прогрев выбранной модели пустым запросом с `keep_alive=30m`, если включён тумблер прогрева
- при выходе: `ollama stop <model>` и завершение процесса `serve`, но только если сервер запускало само приложение; чужой сервер не трогается
- путь к CLI: значение из настроек, иначе первый существующий из `/opt/homebrew/bin/ollama`, `/usr/local/bin/ollama` (Homebrew на Apple Silicon и официальный установщик)

## 7. Разрешения и безопасность

- Accessibility: чтение выделения и отправка `Command-C` (`NSAccessibilityUsageDescription`)
- весь перевод локальный, сетевые вызовы идут только на настроенный адрес Ollama (по умолчанию `localhost:11434`) и на GitHub API при ручной проверке обновлений
- буфер обмена восстанавливается при ошибке перевода
- приложение объявлено как `LSUIElement`: стартует без иконки в Dock, иконка включается политикой активации по настройке

## 8. Сборка и релиз

- `scripts/build_app.sh`: release-сборка SwiftPM, упаковка в `translate&go.app`, ad-hoc codesign
- `scripts/build_dmg.sh`: сборка `.app` + упаковка в `translate-go.dmg` через npm-пакет `create-dmg` (Sindre Sorhus)
- CI (`.github/workflows/ci.yml`): lint через `xcrun swift-format` из тулчейна Xcode, сборка debug, `swift test`, app bundle на каждый push/PR в `main`, артефакт `.app`
- Release (`.github/workflows/release.yml`): по тегу `v*` собирает DMG и публикует в GitHub Release

Важно: используется именно npm-пакет `create-dmg` (опции `--overwrite`, `--no-version-in-filename`, `--dmg-title`, `--no-code-sign`), а не одноимённый brew-инструмент Andrew Janke с другим набором опций.

## 10. Известные ограничения и технический долг

- `CFBundleShortVersionString` в `Info.plist` = `0.0.0` (плейсхолдер) для локальных и CI-сборок; источник истины для версии - git-тег, релизный workflow подставляет его в plist.
- Модель по умолчанию одна (`OllamaDefaults.model` = `translategemma:12b`); фактический выбор идёт из локально установленных моделей.
- Чанки переводятся последовательно, без параллелизма; для очень длинного текста это сказывается на времени.
- Приложение подписано ad-hoc: после каждого обновления macOS заново запрашивает разрешение Accessibility, Gatekeeper предупреждает о неизвестном разработчике. Полное решение - Developer ID + notarization (требует платного Apple Developer аккаунта).
- Изменение адреса сервера Ollama применяется к переводам сразу, но автозапуск/прогрев сервера выполняется один раз при старте приложения со значениями на тот момент.
